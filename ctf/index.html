Play the CTF

A capture-the-flag training game that runs entirely on your own machine. Break into a small, deliberately vulnerable app with synthetic data, then see your attack from the defender's side: what the sensor logged, which technique it matched, and how the hole gets closed.

No account, no leaderboard, nothing to sign up for. The game's own page runs on 127.0.0.1, and the vulnerable app sits on a sealed Docker network with no route out. Nothing you do is sent anywhere unless you choose to share a session.

1Start the game on your machine

You need Docker 28 or newer (Docker Desktop on Mac or Windows; on Linux, older Docker Engine versions could expose "localhost-only" ports to your network). Then, in a terminal:

curl -fsSL https://aaronjadler.github.io/ctf/docker-compose.yml -o cyberguard-ctf.yml
docker compose -f cyberguard-ctf.yml up
Download the compose file

Read the file before you run it. It's short. It should only start two containers from ghcr.io/aaronjadler/, both read-only with every capability dropped, ports bound to 127.0.0.1, and no folders from your computer mounted. If it asks for anything else, don't run it.

Verify the images (optional)

Each image is signed by the build workflow that made it. With cosign:

cosign verify ghcr.io/aaronjadler/cyberguard-agent:latest \
  --certificate-identity-regexp '^https://github.com/AaronJAdler/cyberguard/\.github/workflows/images\.yml@' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com

Run it again with cyberguard-target. The compose file pins each image by digest, so what you verify is what runs.

Stop it with Ctrl+C, and remove everything with docker compose -f cyberguard-ctf.yml down -v.

2Open the game

When the terminal says it's ready, open http://127.0.0.1:8071 in your browser. That page is served by the game on your machine; you pick a challenge, play, and submit flags there.

3Your session stays with you

The game keeps a journal of what you, the sensor and the game's agents did, on your machine only. You can read it, download it or clear it from the game page. If sharing is enabled, you can choose to send one session to help tune the defender; you'll see exactly what would be sent first.

How it works

RangeThe vulnerable app. Internal network only, read-only, synthetic data.
SensorDetection rules tag each request with the technique it used (IDOR, SSRF, SQLi…).
AgentServes the game page on 127.0.0.1, proxies you into the range, keeps the journal.
